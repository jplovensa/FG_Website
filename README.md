# Fjäll Group

A lightweight corporate website built with semantic HTML, CSS and vanilla JavaScript. The architectural monograph direction uses locally hosted Inter, the supplied Fjäll Group logo, white and charcoal surfaces, teal accents and editorial typography inspired by the supplied live Fjäll reference. No frontend framework, external font requests, runtime packages or credentials are required.

## Local development

Use Node.js 22 or newer:

```sh
npm run dev
```

The development server uses port 3000. Set `PORT` to change it. Edit the homepage in `index.html`, editorial additions in `monograph.css`, and project content in `case-studies.js`. Run `npm run build` after changing case-study content; its nine static pages are generated by `scripts/case-pages.js`. The build refreshes generated `projects/*.html` and `sitemap.xml` in both the source root and `dist/`, so local development links and either Pages publishing method work. Do not edit generated pages directly. Use `--dist` to review the production output.

## Build and validate

```sh
npm run build
npm test
node scripts/serve.js --dist
```

The build creates `dist/` with only public site files. Tests check production assets at both the domain root and a repository subpath, video range delivery, and the WhatsApp draft destination and encoding. The build checks JavaScript syntax before replacing the previous output. Browser checks should additionally cover intro completion, refresh replay, skip/Escape, video pause/play, mobile navigation, project filtering and details, reduced motion, and failed video requests.

## GitHub Pages

All asset URLs are relative so the same website works at `https://jplovensa.github.io/FG_Website/` and at the domain root on Vercel.

For publishing through GitHub Actions, open the repository's **Settings → Pages** and choose **GitHub Actions** as the source. The included `.github/workflows/pages.yml` builds, tests and deploys `dist/` on pushes to `main`. If needed, run **Deploy GitHub Pages** manually from the Actions tab after changing the source.

The included GitHub Actions deployment publishes `dist/`. Branch-based Pages publishing from **main / (root)** is also supported: generated project pages and the sitemap are checked in and refreshed by the same build, with `.nojekyll` preserving static delivery.

To reproduce GitHub Pages locally:

```sh
npm run build
node scripts/serve.js --dist --base-path=/FG_Website/
```

Visit the server's `/FG_Website/` path. Requests outside that path intentionally return 404 so broken root-relative URLs are caught during testing.

## Vercel

Import this GitHub repository into Vercel. Select **Other** as the framework. The included `vercel.json` sets `npm run build` as the build command and `dist` as the output directory. No environment variables are needed for the selected WhatsApp-only workflow. Vercel can additionally host the optional `api/inquiry.js` function; it stays inactive without a configured lead destination. The Node server is for local development only. Set `SITE_URL` to the public canonical origin, including any repository path, when using a primary domain other than the current GitHub Pages URL.

## Media and playback

- `assets/intro.mp4` is the complete supplied modular-block opening film, compressed to H.264 with fast-start metadata. It fills the viewport using `object-fit: cover`, which crops the edges on narrow screens rather than letterboxing. The supplied logo reveals during the last 1.25 seconds and briefly holds before opening the website. It plays on homepage load and refresh, with a skip button, Escape key, and an 8.5-second maximum waiting time. Direct links to the inquiry section skip the film, including the return path from project studies.
- `assets/hero.mp4` is the complete supplied hero film, compressed in the same way. Its download begins after the intro closes so the two videos do not compete for bandwidth.
- Both videos are muted and play inline. The hero pauses when offscreen or when the browser tab is hidden.
- Reduced-motion or data-saving preferences bypass the intro and leave a static hero poster; the hero can be played manually. A rejected autoplay request or failed intro download reveals the page immediately.
- Project images are optimized WebP extracts from the supplied 2026 corporate profile and load lazily. Some profile imagery may be architectural renderings; it is presented as imagery from that profile, not as independently verified completion photography.
- Original uploads remain outside the Git checkout. Only optimized web assets are included; no large ZIP or PDF is committed.
- `assets/retrofit.mp4` preserves the complete 51-second Garuda Spark Innovation Hub / Malang Creative Center film and its audio. It is encoded as browser-compatible H.264/AAC at 720p. The player downloads the film only after an explicit click; native controls provide pause, seek, sound and fullscreen. Playback pauses when offscreen or in a hidden tab.
- `assets/fjall-logo.png` is the logo matching the supplied artwork, extracted from the corporate profile with its original embedded transparency mask. It is used in the header, footer and preloader. The favicon uses its geometric mark.

## Interactive experience

`experience.js` owns the five-stage customer journey and animated world map. Visitors can choose home, hospitality, retrofit, modular, mass-scale housing or workers’ accommodation projects; move between stages; play or pause the guided sequence; and download a text starter brief. The lazy-loaded `construction-scene.js` renders a WebGL construction site, guide character, delivery vehicle and staged building components. Forest, mountain and beachfront settings include trees or palms, atmospheric distance, warm directional lighting, simple ground shadows and coastal water. A lower camera angle and optional slow orbit let visitors explore the surroundings. Camera rotation works by dragging, keyboard or buttons. Housing, modular and workers’ accommodation scenes show repeated units; retrofit begins with an existing building. The renderer is self-contained, caps pixel density and frame rate, pauses offscreen or in a hidden tab, and stops drawing settled stages unless a camera orbit is playing. Scene motion and camera orbit have separate controls. Reduced-motion preferences produce static views. If WebGL is unavailable or the context is lost, the original SVG illustration and all journey controls remain available. The scene is an illustrative concept, not an engineering specification or a pricing/timeline calculator. The brief download happens locally and sends no data to a server.

`studio.js` owns the business studies, material library and inquiry handoff. GreenShift's illustration card opens a native modal with brief, structure and coordination stages. FAD's card opens a repeatable housing study with a keyboard-accessible unit-count slider. Each modal also includes a user-controlled 18-second WebGL concept trailer with cinematic camera shots, a character and a surrounding landscape. GreenShift develops three box studies into a curved pavilion at a beachfront, with a designer, model table, continuous form bending and progressive glazing; FAD expands one home into a twelve-home community in a wooded landscape. The local renderer is shared with the customer journey and loaded only when needed. Camera and target motion follow one continuous orbit, rather than chapter cuts. Construction develops through eased geometry, while the character walks and breathes and trees move gently. The shared renderer now uses a deterministic, locally generated 512px texture atlas for plaster, timber, terrain and metal, roughness-aware GGX-style lighting, Fresnel reflections for glazing and water, warm directional light, sky bounce, filmic tone mapping and gamma-correct output. Soft analytic building shadows and layered contact shadows anchor the scene. A procedural sky, rolling hills, tapered tree trunks and individual leaf/frond geometry replace flat scenery and spherical crowns. Trailer cameras sit lower for a more architectural perspective. These are illustrative CGI scenes rather than filmed buildings or a full ray-traced renderer. The complete 16:9 film fits the modal without cropping. Play, pause, replay, seek and MP4 download are available. Reduced-motion preferences start at a static end card. Rendered MP4s provide playback if WebGL is unavailable or lost; trailers stop when the modal closes or becomes hidden. The SVG studies remain available below the films. Native dialogs support Escape, focus containment and focus restoration. The full nine-entry portfolio and flagship film remain available without the retired transformation module.

The material experience studio includes EPS / GX-100 Panel, Bemmel, RoR roof and materials at scale. Visitors select a study, bring illustrated layers together or separate them, and carry the selected topic into an inquiry. All views have accessible descriptions. Visuals and information are sourced from the supplied Product Knowledge deck and optimized RoR Catalogue. GX-100 shows the exact nine-layer build-up, finishes and preparation photography. BEMMELS shows the braided basalt profile and its engineering process. RoR distinguishes rubber with woven-fibreglass reinforcement from overlapping shingles, with site imagery, daylight options, nominal 0.50 m × 4.00 m rolls and the catalogue palette. Document references are shown in each entry. Application renders and trailer scenes are labelled concepts. Final performance, compatibility, installation and project specifications require verification. Layer transitions respect reduced-motion preferences.

The inquiry form validates required name, email or WhatsApp number, and project details, then opens an encoded WhatsApp draft at **+62 877 860 10290**. Visitors review and send it themselves in WhatsApp. The website does not send a message, submit to a backend, retain the fields or claim an inquiry was delivered. Optional company and site details are included in the draft. The direct WhatsApp link remains available, and the form's native fallback sends the project message to WhatsApp. The production content-security policy allows the WhatsApp form destination.

The map uses a lightweight SVG derived from Natural Earth's public-domain [110m land dataset](https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_110m_land.geojson). Connections represent Indonesia as the production base, Sweden as the engineering origin, Japan as a precision/deployment connection, and Australasia as a regional focus; they do not claim offices in every destination. Visitors can select a connection and pause motion. Animation pauses offscreen or in a hidden tab and is disabled for reduced-motion preferences.

Inter is distributed under its included license in `assets/fonts/LICENSE.txt`. The locally hosted variable font is `assets/fonts/inter-latin.woff2`.

## Optional trailer rendering

The checked-in MP4s and posters are generated from the same deterministic WebGL shots as the live player. To regenerate, start the site and run `python scripts/render-trailers.py --url http://localhost:3000/`. This optional offline tool requires Python Playwright, Pillow, Chromium at `/usr/bin/chromium`, and FFmpeg. They are not deployment dependencies. Videos are H.264, 720p, 24 fps, with fast-start metadata.

Business cards play the muted films directly inside their 16:9 frames when visible, with separate pause/play controls. Opening a study pauses both previews. Offscreen and hidden-tab previews pause; reduced-motion and data-saving preferences keep static posters until the visitor opts into playback.

The material studio uses high-resolution AI-assisted illustrations for GX-100, BEMMELS and RoR. They are labelled studio concepts, based on the documented systems, not product certification or completed-project photographs. Original catalogue images remain available in dedicated views, with display size limited to their source resolution. Materials at scale retains the original supplied four-application image. Every material composition uses contain sizing in a consistent studio frame; no source image is cropped.

GreenShift’s coastal water is one static surface, with the land ending at the shoreline and no coplanar foam strips. Its design massing uses continuously deformed mesh geometry, rather than swapping rectangular and curved images. Roof modules do not overlap, and their foundations remain anchored to the plinth. Regenerate only that film with `python scripts/render-trailers.py --kind greenshift --url http://localhost:3000/`.

### Optional future saved inquiries

Enable only after choosing and connecting a durable CRM or form-service receiver. On Vercel, set `LEAD_WEBHOOK_URL` to that receiver’s HTTPS endpoint and optionally `LEAD_WEBHOOK_TOKEN` for its bearer authentication. Do not put credentials into frontend files. The receiver must save the lead and notify the team before acknowledging success. The endpoint validates contact details, field lengths, JSON size, origin and a honeypot; it uses a timeout and rejects redirects. It returns receipt confirmation only after the destination responds successfully. An inactive destination or downstream failure never produces a receipt confirmation. The frontend retains the brief and offers WhatsApp after failure. Verify storage and notifications end to end before relying on this workflow. Static GitHub Pages continues to use WhatsApp and cannot host the API function. No external lead was sent during development tests.
